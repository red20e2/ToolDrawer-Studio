# ToolDrawer Studio V0.1.1 Calibration Workspace Redesign

**Date:** 2026-08-14
**Status:** Approved design
**Target:** V0.1.1 prerelease

## Problem

The V0.1.0 Import & Calibrate screen technically displays imported images, but the image is reduced to a small central preview because the calibration view always fits the entire image while capture, phone, tray, calibration, and status controls consume most of the window height. Portrait photos are especially difficult to use. The current image view also has no user-controlled zoom or pan, so selecting exact calibration references is unnecessarily difficult.

Calibration is a precision interaction. The image must be the primary workspace.

## Goals

- Make the imported photo occupy roughly 80-90% of the working area in normal use.
- Move capture and calibration controls into a narrow contextual right sidebar.
- Add precise zoom, pan, fit, 100%, point selection, point adjustment, and keyboard interactions.
- Preserve full-resolution image coordinates regardless of display zoom or Windows DPI scaling.
- Keep all existing capture and calibration methods working.
- Avoid changes to downstream Detect/Edit, Measure, Arrange, Generate, and Save/Export behavior.

## Non-goals

- Redesigning downstream workflow stages.
- Changing calibration mathematics or manufacturing geometry.
- Adding new calibration methods.
- Replacing the existing image-loading or capture pipelines.
- Changing project schema solely for this UI redesign.

## 1. Workspace Layout

The Import & Calibrate stage will use a horizontal workspace.

### Main image canvas

The image canvas is the dominant region and receives all spare window space. It should normally occupy approximately 80-90% of the application width after the sidebar is accounted for.

The canvas remains visible while sidebar content scrolls. It must not be pushed vertically by capture trays, phone QR content, calibration forms, or warning text.

### Right sidebar

A narrow right sidebar, nominally 300-340 logical pixels wide, contains capture actions, calibration settings, status, and contextual controls.

The sidebar may contract slightly on small displays but the image canvas retains priority.

### Workflow tabs

The existing top-level workflow remains unchanged:

1. Import & Calibrate
2. Detect & Edit
3. Measure
4. Arrange
5. Generate
6. Save & Export

## 2. Image Navigation

### Initial state

A newly loaded image opens in **Fit Image** mode. The complete photo is visible inside the canvas while using as much canvas area as its aspect ratio allows.

### Zoom

- Mouse wheel zooms in and out centered around the pointer location.
- Supported zoom range is 10% through 1600%.
- The current zoom percentage is displayed in the sidebar or canvas toolbar.
- Zoom is a view transform only. It never changes source image dimensions or calibration coordinates.

### Pan

- Middle-mouse drag pans the image.
- Space + left-drag provides an alternate pan gesture.
- Panning is available whenever the image is zoomed beyond the fitted view.

### View commands

- **Fit Image** fits the entire image to the available canvas.
- **100%** displays source image pixels at 1:1 logical image scale.
- Double-click on the canvas invokes Fit Image.

### Resize behavior

Before a user manually zooms or pans, resizing the window keeps the image fitted to the available canvas.

After manual zoom or pan, window resize, maximize, restore, sidebar content changes, and calibration-method changes preserve the user's current view instead of automatically calling Fit Image.

## 3. Calibration Point Interaction

When the active calibration method requires point selection, the image canvas enters calibration-point mode.

### Cursor and placement

- Cursor becomes a crosshair.
- Left-click places required calibration points in order.
- Point labels are clearly numbered.
- Source image coordinates are derived from the graphics scene/image coordinate system, not screen pixels.

### Marker rendering

Markers and labels remain approximately constant in on-screen size while the image zoom changes. Zooming should enlarge the image, not make calibration handles enormous or microscopic.

### Editing points

- Clicking near an existing calibration point selects it.
- A selected point can be dragged for fine adjustment.
- Delete or Backspace removes the selected point.
- Escape clears the active point selection without deleting unrelated points.
- **Clear Points** removes all points for the current calibration operation.

### Paired points

Where a calibration mode uses paired points, a visible line is drawn between the applicable points.

For known-distance calibration, the sidebar previews:

- number of selected points,
- measured pixel distance,
- entered known distance,
- calculated pixels-per-millimeter scale.

This preview is shown before calibration is committed.

## 4. Right Sidebar

### Capture/project actions

The top of the sidebar contains:

- Import Photo
- Webcam
- Phone Capture
- Open Project

Phone-capture status is displayed inline instead of consuming a large permanent region of the screen.

### Calibration controls

The sidebar contains the existing calibration methods:

- Known Distance
- A4 Sheet
- US Letter
- Known-size Object
- Printable Target

Only controls relevant to the selected method are visible.

Primary actions include:

- Clear Points
- Calibrate
- Fit Image
- 100%

### Status

The lower sidebar displays calibration state, confidence, warnings, and the low-confidence tracing override only when relevant.

Long permanent disclaimer text should not consume canvas space. Manufacturing/metrology guidance may be represented compactly in this stage and remains available where export/manufacturing decisions are made.

### Capture tray

The current large pending-capture tray is replaced in this stage by a compact, collapsible thumbnail strip or list in the sidebar.

Selecting a thumbnail loads it into the main canvas. Existing capture promotion behavior remains intact. Contextual actions such as rotate, delete, and add/promote to project are shown beside or beneath the selected capture where supported by the existing workflow.

## 5. Window, Fullscreen, and DPI Behavior

### Window sizing

- Minimum practical size: approximately 1100 x 700 logical pixels.
- Default size: approximately 1400 x 900 logical pixels.
- The application should remember the last normal window size and position when practical within the existing preferences architecture.
- Extra space from maximizing the window is given primarily to the image canvas.

### Sidebar overflow

If vertical space is insufficient, the sidebar scrolls independently. The image canvas remains visible and stable.

### Sidebar collapse

A compact collapse/restore control allows the user to hide the entire right sidebar temporarily. Restoring the sidebar preserves all current settings and calibration state.

### Fullscreen

F11 toggles a fullscreen workspace. Workflow tabs and the right sidebar remain available unless the user has separately collapsed the sidebar.

### High-DPI behavior

The UI must remain usable at Windows display scaling values including 100%, 125%, 150%, 175%, and 200%.

Controls, markers, labels, and handles use logical display units. Calibration calculations always use original image coordinates and are therefore independent of monitor DPI scaling.

## 6. Architecture

### CalibrationImageView responsibilities

`CalibrationImageView` remains responsible for image presentation and calibration-point interaction, but gains explicit view-state behavior:

- fitted vs manually navigated state,
- zoom limits and zoom percentage reporting,
- cursor-centered zoom,
- pan handling,
- Fit Image and 100% commands,
- point selection and drag adjustment,
- view-stable resize behavior,
- constant-screen-size calibration overlays.

The view must not alter calibration-domain math.

### Import & Calibrate stage responsibilities

`MainWindow._capture_stage()` is reorganized from a vertical stack into a main-canvas + right-sidebar composition.

Existing capture services, controller calls, calibration services, and persistence behavior are reused rather than rewritten.

### State boundaries

Image navigation state is transient UI state and must not become manufacturing/project geometry. Calibration point coordinates and committed calibration records retain their existing project/domain meanings.

## 7. Error Handling

- Invalid or unsupported images continue to report a clear load error.
- Fit/100% commands are no-ops when no valid image is loaded.
- Calibration cannot commit until the selected method's required references are valid.
- A failed calibration operation must retain the image and selected points so the user can correct them.
- Sidebar collapsing, fullscreen transitions, and resize events must not discard capture or calibration state.

## 8. Automated Testing

### Image-view tests

Add coverage for:

- portrait image fit behavior,
- landscape image fit behavior,
- initial Fit Image state,
- wheel zoom,
- cursor-centered zoom transformation,
- 10% minimum zoom,
- 1600% maximum zoom,
- Fit Image reset,
- 100% view,
- manual zoom persistence across resize,
- middle-drag pan,
- Space + left-drag pan,
- double-click Fit Image.

### Calibration-point tests

Verify:

- point placement maps correctly to original image coordinates at multiple zoom levels,
- calibration geometry is unchanged by zoom,
- marker screen size is effectively stable while zooming,
- point selection and drag adjustment,
- Delete/Backspace point removal,
- Escape selection cancel,
- Clear Points,
- known-distance pixel-distance preview,
- calculated scale preview,
- calibration-method changes preserve view state,
- sidebar/layout resizing does not modify point coordinates.

### Layout/regression tests

Exercise representative window sizes:

- 1100 x 700
- 1366 x 768
- 1920 x 1080
- 2560 x 1440

Verify that the image canvas remains the dominant workspace and the sidebar can scroll without shrinking the canvas vertically.

Existing automated tests for import, webcam, phone capture, pending capture promotion, calibration modes, tracing gates, project save/load, and downstream stages must continue to pass.

## 9. Manual Release Validation

Before V0.1.1 is published:

1. Launch the packaged Windows build.
2. Import a tall portrait photo containing a tool and dimensional reference.
3. Confirm the image occupies nearly the full usable workspace.
4. Zoom into the dimensional reference.
5. Pan while zoomed.
6. Place calibration points precisely.
7. Drag one point for fine adjustment.
8. Confirm displayed pixel distance and calculated scale update correctly.
9. Maximize, restore, and resize the window.
10. Confirm the manual zoom, pan position, and calibration coordinates remain stable.
11. Test Fit Image and 100%.
12. Collapse and restore the sidebar.
13. Toggle F11 fullscreen.
14. Complete calibration successfully.
15. Continue through Detect/Edit far enough to verify the redesign did not break stage progression.

## 10. Release Strategy

The existing V0.1.0 release artifacts are not replaced or silently modified.

This redesign is delivered as a new **V0.1.1 prerelease** after automated and packaged-Windows validation passes. The physical-manufacturing validation requirement for the overall V0.1 workflow remains separate and unchanged.

## Acceptance Criteria

The redesign is accepted when:

- portrait and landscape photos use the majority of the application workspace,
- the user can accurately zoom, pan, and adjust calibration points,
- calibration point coordinates are invariant under view transforms and DPI scaling,
- resizing no longer unexpectedly resets a manually navigated view,
- the right sidebar contains the existing capture and calibration controls without materially reducing canvas height,
- existing capture/calibration workflows remain functional,
- downstream workflow behavior is unchanged,
- automated tests and packaged-Windows manual validation pass,
- V0.1.1 can be built without altering the published V0.1.0 artifacts.

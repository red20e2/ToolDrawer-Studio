# ToolDrawer Studio V0.1 Measure / Thickness Design

**Date:** 2026-08-12  
**Status:** Approved design, pending written-spec review  
**Repository:** `red20e2/ToolDrawer-Studio`  
**Feature branch:** `feature/v0.1-measure-thickness`  
**Branch base:** capture-workflow head `9141e5107b2899d4d2bc48617424acbd50690063`  
**Depends on:** V0.1 Capture Workflow / PR #3

## 1. Purpose

This slice adds the V0.1 **Measure** stage after top-view capture, calibration, tracing, and contour refinement.

The goal is to let a user attach one calibrated side-view image to a selected tool, estimate the tool's physical maximum thickness automatically, correct or override that estimate when needed, and convert the accepted physical thickness into an explicit manufacturing pocket-depth suggestion.

Physical thickness and manufacturing pocket depth are separate values. ToolDrawer Studio must never silently treat them as interchangeable.

The target workflow is:

`Select Tool -> Add Side View -> Calibrate Side View -> Auto Measure -> Review/Correct -> Accept Thickness -> Suggest Pocket Depth -> Optional Pocket Override`

## 2. Approved Product Decisions

1. A side view is explicitly attached to a selected tool. ToolDrawer Studio does not guess tool-to-photo associations.
2. V0.1 supports one active side view per tool, with a clear Replace Side View action.
3. Every side-view image requires its own calibration. Top-view calibration is never reused automatically for a different photograph.
4. Thickness uses automatic side-profile estimation plus manual correction.
5. The automatic estimator finds the maximum valid physical thickness by default.
6. The automatic measurement endpoints remain visible and editable.
7. Low-confidence automatic measurements cannot drive pocket-depth suggestions until accepted or corrected.
8. High-confidence measurements may become the accepted thickness automatically.
9. Automatic thickness and accepted/manual thickness are stored separately.
10. Measured physical thickness and manufacturing pocket depth are stored separately.
11. Project-level defaults define desired exposed height and bottom clearance; individual tools can override either value.
12. Suggested pocket depth is calculated from accepted thickness, exposed height, and bottom clearance.
13. A manual final pocket-depth override is preserved until the user explicitly replaces or removes it.
14. Existing V1 `.tds` projects must migrate without changing their existing pocket geometry.

## 3. Scope

### 3.1 Included

- One active side-view capture per tool.
- Explicit side-view selection from project/pending captures.
- Side-view replacement.
- Independent side-view calibration using the existing calibration system.
- Automatic side-profile silhouette detection.
- Maximum-thickness estimation.
- Measurement confidence scoring and warnings.
- Visible automatic measurement endpoints.
- Draggable endpoint correction.
- Manual exact thickness entry.
- Reset to automatic measurement.
- Explicit acceptance for low-confidence results.
- Project defaults for exposed height and bottom clearance.
- Per-tool overrides for exposed height and bottom clearance.
- Suggested pocket-depth calculation.
- Manual final pocket-depth override.
- V1 -> V2 `.tds` migration.
- Full save/reopen preservation.
- Deterministic unit, image, integration, and migration tests.

### 3.2 Out of scope

- Multiple side views per tool.
- Automatic fusion of multiple views.
- 3D reconstruction or point clouds.
- Region-specific/stepped depth editing.
- Automatic association of photographs with tools.
- Gridfinity generator changes.
- Foam generator changes.
- Advanced tool-library/versioning work.
- AI-model-based side-view segmentation.

These remain future slices. V0.1 Measure uses deterministic OpenCV/image-processing techniques plus manual correction.

## 4. User Workflow

### 4.1 Enter Measure stage

The user selects an existing traced `ToolObject` and opens the Measure stage.

The panel shows:

- tool name;
- top-view outline preview;
- current side-view state;
- side-view calibration status;
- automatic thickness if available;
- automatic confidence and warnings;
- accepted thickness if available;
- exposed-height effective value;
- bottom-clearance effective value;
- suggested pocket depth when allowed;
- final manufacturing pocket depth.

### 4.2 Attach a side view

The user chooses **Add Side View** and selects a capture already present in the project or available through the capture workflow.

Attaching a side view records the capture ID on the selected tool. It does not delete or consume the capture.

If the tool already has a side view, the UI uses **Replace Side View** and requires a deliberate replacement action. Replacing the side view invalidates the previous automatic side measurement because it was derived from different source pixels. Existing manual final pocket-depth overrides are preserved but marked as potentially stale until the user reviews the new suggestion.

### 4.3 Calibrate the side view

The side-view capture must have its own valid `CalibrationRecord` before automatic or endpoint-derived physical thickness can be accepted.

The existing V0.1 calibration methods remain available:

- A4;
- US Letter;
- ToolDrawer Studio printable target;
- two-point known distance;
- known-size object.

A top-view calibration from another capture cannot be reused by capture ID substitution or inferred scale.

### 4.4 Automatic measure

Once the side view has a valid calibration, **Measure Automatically** runs the thickness estimator.

The estimator returns:

- detected side-profile silhouette;
- automatic maximum thickness in millimetres;
- two image-space measurement endpoints;
- confidence score;
- warnings/reasons for reduced confidence;
- measurement metadata required to redraw the overlay deterministically.

A high-confidence result may immediately become the accepted thickness.

A low-confidence result is displayed but remains unaccepted. It cannot produce an actionable pocket-depth suggestion until the user accepts it or corrects it.

### 4.5 Manual correction

The side-view editor overlays the detected silhouette and a measurement line between the automatic endpoints.

The user can:

- drag either endpoint;
- reset both endpoints to the automatic result;
- explicitly accept a low-confidence automatic result;
- type an exact thickness manually;
- rerun automatic measurement;
- replace the side-view image.

Dragging an endpoint recalculates the endpoint-derived distance through the side-view calibration immediately.

A manually entered exact thickness has precedence over automatic and endpoint-derived values, but those source values remain stored for auditability and reset behavior.

## 5. Pocket-Depth Model

### 5.1 Separation of physical and manufacturing dimensions

`accepted_thickness_mm` represents the physical thickness of the tool.

The manufacturing pocket depth is a separate value.

The existing V0.1 `depth_mm` concept is therefore clarified as manufacturing pocket depth rather than physical tool thickness.

### 5.2 Project defaults

The project stores:

- `default_exposed_height_mm`
- `default_bottom_clearance_mm`

V0.1 defaults:

- exposed height: **4.0 mm**
- bottom clearance: **0.8 mm**

These defaults are ordinary editable project settings, not immutable constants.

### 5.3 Per-tool overrides

Each tool may override either default independently:

- `exposed_height_override_mm`
- `bottom_clearance_override_mm`

A `None` override means the project default is inherited.

The UI must clearly show whether a displayed value is inherited or overridden and provide **Reset to Project Default**.

### 5.4 Suggested depth formula

When an accepted thickness exists and all inputs are valid:

`suggested_pocket_depth_mm = accepted_thickness_mm - effective_exposed_height_mm + effective_bottom_clearance_mm`

Example:

- accepted thickness: 18.0 mm
- exposed height: 4.0 mm
- bottom clearance: 0.8 mm
- suggested pocket depth: 14.8 mm

The formula is a manufacturing suggestion, not an irreversible assignment.

### 5.5 Final pocket depth

The tool has a final manufacturing depth resolved as:

1. `pocket_depth_override_mm`, when present;
2. otherwise a valid `suggested_pocket_depth_mm`;
3. otherwise no derived depth is available.

If a tool already has a manual final pocket-depth override and its thickness is later remeasured, ToolDrawer Studio must not silently replace the override. The UI flags that the suggestion changed and leaves the user's explicit final value intact.

## 6. Domain Model

### 6.1 New measurement result type

Introduce a focused measurement-domain structure such as:

```text
ThicknessMeasurementResult
- automatic_thickness_mm: float
- confidence: float
- top_point_px: ImagePoint
- bottom_point_px: ImagePoint
- warnings: list[str]
- silhouette/overlay data needed by the editor
```

This result represents analysis output and is not itself the project's mutable UI state.

### 6.2 ToolObject additions

`ToolObject` gains explicit measurement/manufacturing fields:

```text
side_view_capture_id: str | None
automatic_thickness_mm: float | None
automatic_thickness_confidence: float | None
automatic_thickness_top_px: ImagePoint | None
automatic_thickness_bottom_px: ImagePoint | None
corrected_thickness_top_px: ImagePoint | None
corrected_thickness_bottom_px: ImagePoint | None
accepted_thickness_mm: float | None
thickness_measurement_mode: automatic | endpoints | manual | none
thickness_accepted: bool
exposed_height_override_mm: float | None
bottom_clearance_override_mm: float | None
pocket_depth_override_mm: float | None
```

The exact Python representation may use dataclasses/enums, but the semantics above are required.

### 6.3 Project additions

`Project` gains:

```text
default_exposed_height_mm: float = 4.0
default_bottom_clearance_mm: float = 0.8
```

Internal units remain millimetres.

## 7. Thickness Measurement Service

### 7.1 Responsibility

Create a dedicated `ThicknessMeasurementService` rather than placing OpenCV analysis in Qt widgets or `ToolObject`.

Conceptual interface:

```text
measure(side_view_image, calibration) -> ThicknessMeasurementResult
```

The service owns deterministic image analysis only. It does not mutate the project or UI.

### 7.2 Pipeline

The V0.1 automatic pipeline is:

1. Consume the normalized decoded side-view image.
2. Validate the side-view calibration.
3. Apply the calibration/perspective transform needed for measurement.
4. Generate foreground/tool silhouette candidates using deterministic OpenCV operations.
5. Clean small isolated artifacts conservatively.
6. Select the most plausible tool silhouette.
7. Estimate the tool's principal/long axis from the silhouette.
8. Evaluate calibrated cross-sections approximately perpendicular to the principal axis.
9. Find the maximum valid cross-section thickness.
10. Record the two contour endpoints responsible for that measurement.
11. Convert the distance into millimetres using the calibrated geometry.
12. Score confidence and produce warnings.
13. Return the immutable analysis result.

The principal-axis approach avoids assuming that the user photographed the tool perfectly horizontal or vertical.

### 7.3 Confidence

Thickness measurement has a dedicated confidence threshold independent from the tracing threshold.

V0.1 default automatic-accept threshold: **0.80**.

This is an internal product constant for V0.1, not a user-facing advanced setting.

Confidence decreases for conditions including:

- silhouette touching an image boundary;
- low foreground/background contrast;
- heavy shadow or reflection;
- fragmented silhouette;
- ambiguous competing foreground components;
- extreme perspective or poor calibration residual;
- unusually short/noisy valid cross-section;
- several conflicting maximum candidates;
- geometrically implausible result.

Confidence is advisory, but its threshold controls whether automatic output is allowed to become accepted without an explicit user action.

### 7.4 Failure behavior

Automatic measurement failure never blocks the project.

When automatic analysis cannot return a reliable result:

- the UI explains the failure/warning;
- the side-view image remains available;
- manual endpoint correction remains available when calibration permits;
- exact manual thickness entry remains available.

## 8. UI Design

### 8.1 Measure panel

The dedicated Measure panel contains:

- tool selector/current tool identity;
- top-view outline preview;
- side-view image editor;
- side-view calibration status;
- automatic thickness and confidence;
- warning list;
- accepted thickness;
- effective exposed height;
- effective bottom clearance;
- suggested pocket depth;
- final pocket depth;
- override/inheritance indicators.

### 8.2 Actions

Required actions:

- **Add Side View**
- **Replace Side View**
- **Calibrate Side View**
- **Measure Automatically**
- **Accept Measurement**
- **Reset to Automatic**
- **Enter Thickness Manually**
- **Use Suggested Pocket Depth**
- **Override Pocket Depth**
- **Reset to Project Default** for each overridable project default

### 8.3 Confidence gate

High confidence (`>= 0.80`):

- automatic result may become accepted automatically;
- suggested pocket depth becomes available immediately if the depth inputs are valid.

Low confidence (`< 0.80`):

- automatic result and overlay remain visible;
- warnings remain visible;
- accepted thickness is not updated automatically;
- derived pocket depth is blocked until explicit acceptance, endpoint correction, or exact manual entry.

### 8.4 Stale-result behavior

Changes that invalidate or potentially stale an analysis result must be explicit.

Examples:

- replacing the side-view capture invalidates automatic endpoints and automatic thickness;
- changing side-view calibration invalidates measurements derived from the prior transform;
- re-running automatic measurement replaces the automatic source result but preserves explicit final pocket overrides;
- changing accepted thickness or project/override depth settings recalculates the suggestion immediately.

## 9. Validation and Error Handling

The domain/controller layer validates the following before permitting derived manufacturing depth:

- selected tool exists;
- side-view capture exists;
- side-view calibration exists and is usable;
- accepted thickness is finite and greater than zero;
- exposed height is finite and non-negative;
- bottom clearance is finite and non-negative;
- exposed height is not so large that the formula produces a non-positive pocket depth;
- suggested/final pocket depth is finite and greater than zero;
- endpoint-derived distances use two valid points within the source image/calibrated plane.

Automatic analysis warnings include:

- missing calibration;
- poor calibration confidence/residual;
- no usable silhouette;
- multiple ambiguous silhouettes;
- silhouette at image boundary;
- poor contrast;
- shadow/reflection ambiguity;
- implausible thickness result.

Invalid math never creates negative CAD dimensions. The user must correct the conflicting values.

## 10. Controller Boundaries

The `WorkflowController` coordinates project mutation and owns the transition from analysis output to accepted project state.

Responsibilities include:

- attach/replace side-view capture;
- locate side-view calibration;
- invoke `ThicknessMeasurementService`;
- store automatic result;
- enforce confidence acceptance rules;
- apply corrected endpoints;
- apply exact manual thickness;
- calculate effective project/tool depth settings;
- calculate suggested pocket depth;
- preserve manual final pocket-depth overrides;
- invalidate stale measurements after source/calibration changes.

Qt widgets must not directly mutate persistence structures or perform OpenCV measurement calculations.

## 11. `.tds` Schema V2 and Migration

### 11.1 Why schema V2 is required

Current V1 projects store only the earlier `ToolObject.depth_mm` manufacturing value and do not contain side-view measurement state or project-level pocket defaults.

This slice introduces schema version 2 and the first explicit schema migration path.

### 11.2 V1 -> V2 migration

When loading a valid schema V1 project:

- preserve every capture and calibration unchanged;
- preserve every contour and trace value unchanged;
- map each existing `ToolObject.depth_mm` to `pocket_depth_override_mm`;
- set `side_view_capture_id = None`;
- set automatic/accepted thickness fields to `None`/unaccepted;
- set per-tool exposed-height and bottom-clearance overrides to `None`;
- initialize project defaults to 4.0 mm exposed height and 0.8 mm bottom clearance;
- do not derive a new pocket depth for migrated tools;
- preserve the old manufacturing pocket depth exactly through the override.

Loading is therefore non-destructive.

Saving a migrated project writes schema V2.

### 11.3 Migration architecture

Replace single-version rejection with an explicit migration path.

Conceptually:

```text
read manifest/project payload
-> validate supported historical schema
-> migrate sequentially to current schema
-> construct current domain model
```

Future migrations can then add V2 -> V3 without embedding unrelated compatibility logic throughout `_project_from_dict`.

Unsupported future schema versions remain rejected rather than guessed.

### 11.4 V2 persistence requirements

V2 save/reopen preserves:

- side-view capture association;
- side-view calibration association through capture/calibration IDs;
- automatic thickness;
- automatic confidence;
- automatic endpoints;
- corrected endpoints;
- accepted thickness;
- measurement mode/acceptance state;
- project depth defaults;
- per-tool overrides;
- manual final pocket-depth override;
- sufficient state to reconstruct the Measure panel without re-running image analysis.

## 12. Testing Strategy

### 12.1 Unit tests

Add tests for:

- depth formula;
- default inheritance;
- independent per-tool overrides;
- manual pocket-depth override precedence;
- automatic vs accepted thickness;
- high-confidence automatic acceptance;
- low-confidence gate;
- exact manual thickness precedence;
- endpoint-derived calibrated distance;
- reset-to-automatic behavior;
- stale-result invalidation;
- impossible/negative geometry rejection;
- V1 -> V2 migration;
- V2 serialization round trip.

### 12.2 Deterministic image-analysis fixtures

Generate synthetic fixtures in tests rather than depending on uncontrolled photographs.

Fixtures cover:

- rectangular side profile;
- tapered side profile;
- irregular/handled side profile;
- rotated profile;
- noisy background;
- shadow-like artifact;
- fragmented silhouette;
- boundary-touching object;
- multiple foreground candidates;
- deliberately poor contrast.

Expected measurements use calibrated known geometry so error can be asserted numerically.

### 12.3 Integration tests

Required end-to-end test:

`existing traced tool -> select side capture -> calibrate -> automatic measure -> accept/correct -> compute suggestion -> save .tds -> reopen`

Verify that capture association, calibration relationship, endpoints, automatic result, confidence, accepted value, defaults/overrides, and pocket state survive unchanged.

Additional integration cases:

1. Low-confidence result -> pocket suggestion blocked -> user accepts/corrects -> suggestion becomes available.
2. Manual exact thickness -> save/reopen -> manual value retains precedence.
3. Manual final pocket override -> remeasure -> override remains unchanged and suggestion changes separately.
4. V1 project -> migrate -> old pocket depth unchanged -> save V2 -> reopen V2.
5. Replace side view -> old measurement invalidated -> final explicit pocket override preserved.

### 12.4 Existing-suite regression requirement

All existing capture, calibration, tracing, editor, persistence, CAD/export, controller, and UI tests must remain green on Windows CI.

## 13. Success Criteria

The slice is complete when all of the following are true:

1. A user can explicitly attach one side-view capture to a traced tool.
2. The side view must be independently calibrated.
3. Automatic measurement returns maximum calibrated thickness and visible endpoints for good synthetic/realistic inputs.
4. Low-confidence automatic output cannot silently drive manufacturing depth.
5. The user can correct endpoints or enter exact physical thickness manually.
6. Project defaults and per-tool overrides produce deterministic pocket-depth suggestions.
7. Manual final pocket-depth overrides are never silently replaced.
8. `.tds` V2 stores all Measure state and reopens without re-analysis.
9. V1 `.tds` files migrate without changing existing manufacturing depth.
10. The full Windows CI suite passes.

## 14. Implementation Boundary

The preferred architecture is a dedicated measurement subsystem with focused domain contracts, controller orchestration, and a dedicated Measure UI panel.

Do not implement general multi-dimensional metrology, multiple-view fusion, region-depth editing, 3D reconstruction, Gridfinity changes, or foam changes as part of this slice.

The next implementation plan should decompose the work into TDD-sized tasks covering schema migration, domain/depth rules, measurement service, controller integration, UI editor, persistence, end-to-end tests, and Windows verification.

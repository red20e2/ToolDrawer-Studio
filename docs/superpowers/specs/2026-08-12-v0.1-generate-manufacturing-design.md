# V0.1 Generate / Manufacturing Design

Date: 2026-08-12
Status: Approved design
Branch: `feature/v0.1-generate-manufacturing`

## Goal

Add the first complete organizer-generation stage to ToolDrawer Studio so a project can flow from calibrated tool geometry and measured pocket depth through Arrange into a validated, manufacturable foam/drawer or Gridfinity organizer, then export the complete organizer as STEP, STL, and DXF.

The feature must preserve the separation of responsibilities already established in the application:

- Detect/Edit owns the calibrated 2D tool contour.
- Measure owns the resolved pocket depth.
- Arrange owns X/Y placement, rotation, locks, grab-side intent, spacing, and layout validity.
- Generate owns manufacturing settings, manufacturing validation, organizer solids, preview state, and organizer-level export readiness.
- Export writes files. It does not invent or repair geometry.

Generate must never silently move tools, reduce spacing, alter measured depth, or weaken manufacturing constraints.

## Chosen Architecture

Use a dedicated `generation` package rather than expanding the existing single-tool `geometry/pocket.py` path.

Proposed modules:

```text
src/tooldrawer_studio/generation/
    __init__.py
    models.py
    validation.py
    cavities.py
    scoops.py
    foam.py
    gridfinity.py
    builder.py
```

Responsibilities:

- `models.py`: persistent generation settings and derived generation/readiness result contracts.
- `validation.py`: manufacturing-specific validation and warning production.
- `cavities.py`: convert authoritative tool + measurement + placement data into 3D cutters.
- `scoops.py`: finger-access cutter construction and collision-aware automatic sizing.
- `foam.py`: foam/drawer outer body generation.
- `gridfinity.py`: Gridfinity-compatible body, underside, magnets, screws, and stacking geometry.
- `builder.py`: top-level orchestration that validates inputs, builds the outer body, applies cavities/features, checks the final solid, and returns a generation result.

The existing `geometry/pocket.py` and single-tool export path may remain temporarily for compatibility/regression tests during implementation, but the normal V0.1 UI must use organizer-level generation.

## Source of Truth and Data Flow

The generated CAD solid is derived data and is not the authoritative project state.

```text
Edited calibrated tool contour
        +
Tool manufacturing clearance
        -> cleared cavity footprint

Resolved Measure pocket depth
        +
Arrange X / Y / rotation / grab side
        +
Generation settings
        -> manufacturing validation
        -> organizer CAD solid
        -> preview
        -> STEP / STL / DXF
```

For each placed tool, Generate must:

1. use the current edited calibrated contour;
2. apply the tool's manufacturing clearance;
3. rotate by the exact saved Arrange rotation;
4. translate to the exact saved Arrange X/Y placement;
5. resolve that tool's final pocket depth from Measure;
6. extrude a cavity cutter downward from the organizer top by that resolved depth;
7. subtract the cavity from the organizer;
8. add the configured grab-side scoop where applicable.

Different tools in the same organizer may have different cavity depths.

## Project Schema V4

Generate advances `.tds` persistence from schema V3 to schema V4.

V4 adds persistent generation settings and generation review/currentness metadata. It does not store a serialized CadQuery BREP/STL as project authority.

### Generation settings

The project must persist a `GenerationSettings`-equivalent contract with at least:

- `height_mode`: `auto` or `manual`;
- `manual_height_mm`: optional exact organizer height when manual mode is selected;
- `minimum_floor_mm`: default `2.0`;
- `minimum_wall_mm`: default `2.0`;
- `scoops_enabled`: default `true`;
- scoop automatic-sizing settings needed to reproduce the same result;
- Gridfinity options described below;
- mode-specific options required to deterministically rebuild the organizer;
- `review_required` or equivalent persistent readiness marker;
- a deterministic input fingerprint/revision marker sufficient to determine whether the last generated preview/export state matches current project inputs.

The generated CAD model itself is rebuilt from authoritative project state when Generate is explicitly run.

### V3 -> V4 migration

Migration must be non-destructive:

- preserve captures;
- preserve calibrations;
- preserve all tool contours and per-tool manufacturing clearance;
- preserve Measure state, accepted thicknesses, overrides, and resolved-depth inputs;
- preserve Arrange mode, dimensions, placements, rotations, locks, grab sides, spacing, borders, and snap settings;
- add V4 generation defaults;
- do not generate a model;
- do not change a saved arrangement;
- do not pretend an old project has a current generated preview.

## Organizer Height Rules

### Automatic height

Automatic height is the default.

For foam/drawer mode, the minimum required body height is:

```text
max(resolved pocket depth for every placed tool) + minimum_floor_mm
```

The automatic foam/drawer body height is that required value unless a later mode-specific rule requires more material for another enabled feature.

For Gridfinity mode, automatic height must also satisfy the Gridfinity base/feature geometry and, when height snapping is enabled, round upward to the next compatible 7 mm vertical increment. The result must never round downward below the manufacturing requirement.

### Manual height

Manual height uses the exact user-entered height. It is a hard error when the selected height cannot satisfy pocket depth, minimum floor, Gridfinity base, magnet, screw, or other enabled feature constraints.

## Validation Model

Arrange validation and manufacturing validation remain separate layers.

Generate first requires a valid, reviewed Arrange state. It then performs manufacturing-specific validation without modifying project state.

### Hard errors

Hard errors block organizer generation/export. They include at least:

#### Arrange/input readiness

- no Arrange layout exists;
- Arrange layout is marked `review_required`;
- Arrange hard validation fails;
- an intended tool is unplaced;
- a placement references a missing tool;
- a placed tool has no resolved pocket depth;
- a placed tool has thickness/depth review required;
- a resolved depth is non-finite, zero, or negative.

#### Vertical manufacturing

- cavity depth violates `minimum_floor_mm`;
- manual organizer height is insufficient;
- scoop depth violates minimum floor;
- enabled Gridfinity underside/magnet/screw features conflict vertically with a cavity or leave insufficient material;
- organizer dimensions or height are invalid.

#### Horizontal manufacturing

- cavity breaks through the organizer boundary;
- scoop breaks through an unintended outside wall;
- remaining material between manufacturing cuts falls below `minimum_wall_mm`;
- Gridfinity base features and cavity geometry create invalid/intersecting geometry that cannot be resolved under the documented feature-precedence rules.

#### CAD integrity

- invalid/self-intersecting source contour that cannot produce a valid offset;
- failed offset/boolean operation;
- empty final result;
- final result is not a valid solid suitable for export.

### Warnings

Warnings do not block generation/export. Examples include:

- remaining material is valid but close to the configured minimum;
- an unusually deep cavity;
- an automatic scoop had to shrink within its allowed range;
- a stacking lip had to be locally omitted because tool access/cavity geometry takes precedence.

Warnings must identify the affected tool or feature where possible.

### Error language

UI-facing errors must explain the actual manufacturing problem and the required corrective action. Raw CadQuery/OpenCascade errors may be retained for diagnostics but must not be the primary user message.

Example:

```text
Ratchet 3/8": cavity depth 18.4 mm leaves only 1.6 mm floor.
Minimum floor is 2.0 mm. Increase organizer height to at least 20.4 mm
or reduce the resolved pocket depth.
```

## Foam / Drawer Generator

V0.1 foam/drawer mode generates one continuous rectangular solid insert.

Requirements:

- exact width and height come from the Arrange foam/drawer boundary;
- flat bottom;
- one-piece solid;
- automatic or manual total body height;
- exact multi-tool/multi-depth cavities;
- grab-side scoops;
- no artificial internal cell boundaries;
- complete organizer STEP/STL/DXF export.

Multi-layer foam, laminated stepped foam, and separate upper/lower foam sheets are deferred until after the single-body manufacturing path is proven.

## Scoop / Grab Access Geometry

Arrange's `grab_side` becomes manufacturing geometry in Generate.

Default behavior:

- `none`: no scoop;
- `left`, `right`, `top`, `bottom`: generate an automatic smooth rounded finger-access scoop on that side;
- scoop orientation rotates with the tool placement;
- automatic scoop size derives from the cavity geometry, available Arrange grab clearance, organizer boundary, and manufacturing constraints;
- automatic sizing may shrink the scoop to remain valid;
- automatic sizing may never violate minimum floor or minimum wall constraints;
- a scoop that cannot be made valid produces a clear validation result rather than silently weakening constraints.

V0.1 requires per-tool `Auto` and `Off` scoop behavior. Fully custom numeric per-tool scoop dimensions are optional for V0.1 and must not delay the core generator.

## Full-Featured Gridfinity Generator

V0.1 uses the full-featured Gridfinity option selected for this release.

### Compatibility target

- 42.0 mm grid pitch;
- standard Gridfinity-compatible underside/base engagement profile;
- 7 mm vertical unit system;
- a continuous top/cavity region across multiple cells;
- cavities may cross nominal cell boundaries;
- parametric CadQuery geometry, not an imported STL dependency.

The implementation must use one explicit, test-backed Gridfinity profile definition rather than scattered magic numbers.

### Magnets

Magnets are supported and enabled by default.

Default settings:

- diameter: `6.0 mm`;
- depth: `2.0 mm`;
- standard corner-compatible placement;
- repeated/coincident cuts in multi-cell bodies are deduplicated.

Magnet diameter/depth remain configurable and persist in V4.

### Screw holes

Screw holes are independently configurable and disabled by default.

Default settings:

- M3-compatible;
- clearance-hole diameter: `3.2 mm`;
- combined magnet + screw geometry is allowed only when the resulting body remains valid.

### Stacking lip

Stacking lip is enabled by default.

Tool fit and removal access take precedence over top stacking geometry. If a cavity/scoop conflicts only with the stacking lip, the generator may locally omit the lip around that interference and emit a warning. It must not deform or move the tool cavity to preserve stacking.

If an interference cannot be solved by local lip omission without invalidating the body, it becomes a hard error.

### Height snapping

Gridfinity height snapping is enabled by default. Automatic height rounds upward to a compatible 7 mm increment after satisfying pocket depth, minimum floor, base, and enabled feature requirements.

Manual height mode may use an exact millimetre value. If the manual value is not a compatible snapped height, the UI may warn, but it must still validate the actual geometry and never silently change the manual value.

### Gridfinity persisted options

At minimum:

- grid columns/rows remain authoritative in Arrange;
- pitch remains authoritative in Arrange/project defaults;
- magnets enabled;
- magnet diameter;
- magnet depth;
- screw holes enabled;
- screw diameter;
- stacking lip enabled;
- Gridfinity height snapping enabled.

### Gridfinity-specific hard checks

- magnet pocket intersects a tool cavity in an invalid way;
- screw hole intersects a tool cavity in an invalid way;
- floor/material above or around recesses is too thin;
- combined magnet/screw geometry is impossible;
- cavity interferes with required base-engagement geometry;
- final body is not a valid solid.

Stacking-lip-only interference is normally a warning when local omission solves it.

## Stale and Current Generation State

Generation is explicit.

The UI state is conceptually:

```text
Needs generation -> Generated/current -> Inputs changed/review required
```

A generated preview/export becomes stale when any input that affects the solid changes, including:

- tool contour;
- tool manufacturing clearance;
- resolved pocket depth or its measurement inputs;
- Arrange position;
- Arrange rotation;
- Arrange boundary dimensions/mode;
- grab side;
- generation settings;
- scoop behavior;
- Gridfinity options.

Changing settings or upstream data must not automatically regenerate CAD and must not move tools.

Organizer export is enabled only when the generated state/fingerprint matches the current authoritative inputs and no hard validation error exists.

## Generate UI

Stage 5 replaces the existing Pocket Settings stage.

The six-stage workflow becomes:

1. Import & Calibrate
2. Detect & Edit
3. Measure
4. Arrange
5. Generate
6. Save & Export

Generate contains three logical areas.

### Settings

Common settings:

- auto/manual organizer height;
- manual height when selected;
- minimum floor;
- minimum wall;
- scoops enabled.

Foam mode shows foam-relevant controls only.

Gridfinity mode additionally shows:

- magnets enabled;
- magnet diameter;
- magnet depth;
- screw holes enabled;
- screw diameter;
- stacking lip enabled;
- Gridfinity height snap enabled.

### Validation panel

- green/current/ready state;
- yellow warnings;
- red blocking errors;
- errors and warnings identify actual tool names/features where possible.

### 3D preview

The generated organizer preview must show the actual solid, cavities, scoops, and Gridfinity features as applicable, with orbit/pan/zoom interaction.

Generation occurs from an explicit Generate/Regenerate action. Editing a control marks the preview stale rather than launching repeated CadQuery rebuilds for every spin-box change.

## Export

Stage 6 remains separate because saving an editable project and exporting manufacturing files are distinct actions.

### Save Project

- save editable `.tds` V4 project.

### Manufacturing exports

Normal UI actions:

- Export STEP;
- Export STL;
- Export DXF;
- Export All.

Organizer-level filenames use the project/organizer name, for example:

```text
My_Drawer.step
My_Drawer.stl
My_Drawer.dxf
```

### STEP

Export the complete BREP organizer and treat STEP as the preferred CAD/CNC interchange output.

### STL

Export the complete printable organizer mesh.

### DXF

Export a useful top/profile manufacturing representation containing at least:

- outer organizer boundary;
- cavity outlines;
- feature/layer separation where practical and deterministic.

DXF does not need to encode the full 3D Gridfinity underside.

### Export blocking

Manufacturing export is blocked when:

- generation has never been run for current inputs;
- generated inputs are stale;
- a hard validation error exists.

Warnings are shown clearly but do not block export.

## Determinism

Given the same V4 project inputs, generation settings, CadQuery/OpenCascade version, and supported platform, the feature must choose the same body dimensions, cavity transforms, scoop decisions, Gridfinity feature placement, and export topology intent.

No randomized optimization or silent tolerance relaxation is part of V0.1.

Implementation must add automated coverage for at least:

- V3 -> V4 migration;
- V4 round-trip persistence;
- V4 migration does not invent a generated model;
- automatic organizer height;
- manual height validation;
- distinct pocket depths in one organizer;
- translated and rotated cavities;
- manufacturing clearance;
- minimum floor validation;
- minimum wall validation;
- scoop direction after tool rotation;
- scoop automatic shrinking/collision handling;
- scoop disable behavior;
- stale generation state/fingerprint;
- foam body generation;
- multi-cell Gridfinity body;
- 42 mm Gridfinity pitch behavior;
- 7 mm Gridfinity height snapping;
- magnet pockets;
- screw holes;
- combined magnet/screw geometry;
- stacking lip;
- local stacking-lip omission warning;
- Gridfinity/cavity collision validation;
- valid final CadQuery solid checks;
- complete STEP export;
- complete STL export;
- complete DXF export;
- reopening a project does not silently regenerate;
- MainWindow Generate workflow integration;

Windows CI must add a direct generation import/build sanity check alongside the current Arrange/Shapely sanity import and must run the complete pytest suite.

## Merge Gate

The feature is ready for `main` only when all of the following are true:

1. this design spec is approved and committed;
2. a detailed implementation plan is committed;
3. implementation follows TDD for feature behavior and regressions;
4. full test suite passes;
5. Windows GitHub Actions passes on the exact PR head/merge ref;
6. exact head and merge-ref SHAs are recorded during final verification;
7. no unresolved review findings remain;
8. `main` has not moved after the tested merge ref, or the merge ref is revalidated if it has;
9. merge occurs only after explicit user authorization.

## Explicit V0.1 Deferrals

The following are outside this Generate slice:

- multi-layer/laminated foam generation;
- stepped multi-sheet foam manufacturing plans;
- custom polygon drawer boundaries;
- automatic re-arrangement to repair manufacturing failures;
- randomized/genetic/global optimization;
- AI-generated geometry;
- storing generated BREP/STL as authoritative project data;
- arbitrary user-authored custom Gridfinity profiles;
- custom numeric per-tool scoop sizing if it threatens the core schedule.

## Acceptance Criteria

V0.1 Generate / Manufacturing is complete when a user can open or create a valid project, resolve tool depths, arrange all intended tools, configure foam/drawer or full-featured Gridfinity generation, explicitly generate a valid complete organizer, inspect clear manufacturing validation results, preview the resulting 3D solid, save the editable V4 project, and export complete organizer STEP/STL/DXF files without the generator changing authoritative Measure or Arrange state.

# ToolDrawer Studio V0.1 Capture Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add safe Windows webcam capture and temporary local-LAN phone upload with a shared pending-capture tray that promotes selected images into the existing calibration/tracing/project workflow.

**Architecture:** Add focused capture services under `src/tooldrawer_studio/capture/`: canonical byte ingestion, transient pending captures, private-IPv4 selection, a token-authenticated phone session, a narrow HTTP adapter, and an abstracted webcam backend. PySide6 widgets consume those services, while `WorkflowController` remains the single bridge that turns approved capture bytes into persistent project `CaptureAsset` objects.

**Tech Stack:** Python 3.12, PySide6/Qt, OpenCV, Python standard-library networking/HTTP, `qrcode>=8,<9`, pytest, GitHub Actions Windows CI.

## Global Constraints

- Windows desktop remains the primary platform.
- Core capture works locally/offline; phone transfer needs only a shared local network.
- One QR session accepts multiple photos until manual **Stop** or 30 minutes of defined inactivity.
- Only an authenticated upload-page load or successfully accepted upload refreshes the inactivity timer.
- Invalid-token, malformed, rejected, and unrelated traffic never refreshes inactivity.
- Bind only to a resolved RFC1918 private IPv4 address; fail closed if none is available.
- If the bound private IPv4 disappears while the session is active, stop that session and require a fresh one.
- No cloud relay, account, permanent service, NAT traversal, internet-facing listener, third-party page resources, or filesystem serving.
- Existing image limits remain exact: 50 MB source bytes and 40 megapixels decoded.
- Phone and webcam images use one transient pending-capture model and one tray.
- Rotation is limited to 90-degree increments while pending; promotion writes that orientation as the project capture.
- **Add to Project** is non-consuming: the promoted item and every unrelated pending item remain in the tray until explicitly deleted or application exit.
- Unpromoted pending items are session-only; V0.1 has no tray crash recovery.
- HEIC codec work, side-view measurement, AI tracing changes, layout/Gridfinity/foam, and advanced multi-view association are out of scope.
- Full Windows GitHub Actions tests must pass before completion.

```python
def load_new_image_bytes(raw: bytes, filename: str, capture_id: str) -> LoadedImage:
    safe_name = Path(filename).name or "capture.png"
    pixels = _decode_pixels(raw, safe_name)
    height, width = pixels.shape[:2]
    suffix = Path(safe_name).suffix.lower()
    stored_raw = raw
    if suffix not in SUPPORTED_ARCHIVE_SUFFIXES:
        suffix = ".png"
        safe_name = f"{Path(safe_name).stem or 'capture'}.png"
        ok, encoded = cv2.imencode(".png", pixels)
        if not ok:
            raise ValueError("Could not encode normalized image")
        stored_raw = encoded.tobytes()
    asset = CaptureAsset(
        id=capture_id,
        filename=safe_name,
        width_px=width,
        height_px=height,
        archive_path=f"images/{capture_id}{suffix}",
    )
    return LoadedImage(asset=asset, pixels_bgr=pixels, original_bytes=stored_raw)
```

Implement `rotated_png_bytes()` with `np.rot90(..., k=-turns)` so positive turns are clockwise.

```python
CaptureSource = Literal["phone", "webcam"]

@dataclass(slots=True)
class PendingCapture:
    id: str
    source: CaptureSource
    filename: str
    captured_at: datetime
    loaded: LoadedImage
    quarter_turns: int = 0

@dataclass(frozen=True, slots=True)
class PromotionPayload:
    filename: str
    raw: bytes

class CaptureSessionService:
    def __init__(self) -> None:
        self._items: list[PendingCapture] = []
        self._selected_id: str | None = None

    def add_bytes(self, source: CaptureSource, raw: bytes, filename: str) -> PendingCapture:
        if source not in ("phone", "webcam"):
            raise ValueError("Unknown capture source")
        pending_id = str(uuid4())
        loaded = load_new_image_bytes(raw, filename, pending_id)
        item = PendingCapture(pending_id, source, loaded.asset.filename, datetime.now(timezone.utc), loaded)
        self._items.append(item)
        self._selected_id = pending_id
        return item

    def items(self) -> tuple[PendingCapture, ...]:
        return tuple(self._items)
```

Implement the remaining methods with ID lookup that raises `KeyError` for unknown IDs. `preview_png()` always applies pending rotation. `promotion_bytes()` returns original validated bytes/name when `quarter_turns % 4 == 0`; otherwise it returns rotated PNG bytes and a `.png` filename. Promotion never removes the item.

2. if still active and production address discovery no longer contains `bound_host`, stops the session/server.

`stop()` first invalidates `PhoneSession`, then calls `shutdown()` and `server_close()`. Join each thread with a bounded timeout; never wait indefinitely on client threads.

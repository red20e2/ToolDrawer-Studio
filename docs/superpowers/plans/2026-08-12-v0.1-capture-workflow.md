# ToolDrawer Studio V0.1 Capture Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add safe Windows webcam capture and temporary local-LAN phone upload with a shared pending-capture tray that promotes selected images into the existing calibration/tracing/project workflow.

**Architecture:** Add focused capture-domain services under `src/tooldrawer_studio/capture/`: validated byte ingestion, transient pending captures, a narrow token-authenticated LAN upload session/server, and an abstracted webcam backend. The PySide6 UI consumes those services through a capture tray and webcam/phone controls, while `WorkflowController` remains the canonical bridge that turns approved capture bytes into persistent project `CaptureAsset` objects.

**Tech Stack:** Python 3.12, PySide6/Qt, OpenCV, Python standard-library networking/HTTP, `qrcode>=8,<9`, pytest, GitHub Actions Windows CI.

## Global Constraints

- Windows desktop remains the primary platform.
- Core capture works locally/offline; LAN phone transfer requires only that phone and PC share a local network.
- Phone session accepts multiple photos until manual **Stop** or 30 minutes of defined inactivity.
- Only authenticated upload-page loads and successfully accepted uploads refresh inactivity.
- Invalid-token, malformed, rejected, and unrelated traffic do not refresh inactivity.
- Bind only to a resolved private/local IPv4 address; fail closed when none is suitable.
- No cloud relay, account, permanent service, NAT traversal, internet-facing listener, third-party web resources, or filesystem serving.
- Existing image limits remain exact: 50 MB source bytes and 40 megapixels decoded.
- Phone and webcam images share one transient pending-capture model and tray.
- Pending rotation is in 90-degree increments; promotion writes the selected orientation as the canonical project capture.
- Promoting one pending item must not delete unrelated pending items.
- Unpromoted pending items are session-only and need no crash recovery in V0.1.
- HEIC codec work, side-view measurement, AI tracing changes, layout/Gridfinity/foam, and advanced multi-view association are out of scope.
- Full Windows GitHub Actions test suite must pass before completion.

- [ ] **Step 3: Implement canonical new-byte loader and rotation helper**

Use `_decode_pixels()` rather than duplicating limits. Only use `Path(filename).suffix.lower()` to choose a safe archive extension; if suffix is outside `{'.jpg', '.jpeg', '.png', '.bmp', '.tif', '.tiff', '.webp'}`, store promoted bytes as `.png` after normalization.

```python
def load_new_image_bytes(raw: bytes, filename: str, capture_id: str) -> LoadedImage:
    pixels = _decode_pixels(raw, filename)
    height, width = pixels.shape[:2]
    suffix = Path(filename).suffix.lower()
    if suffix not in SUPPORTED_ARCHIVE_SUFFIXES:
        suffix = ".png"
        ok, encoded = cv2.imencode(".png", pixels)
        if not ok:
            raise ValueError("Could not encode normalized image")
        raw = encoded.tobytes()
    asset = CaptureAsset(
        id=capture_id,
        filename=Path(filename).name or f"capture{suffix}",
        width_px=width,
        height_px=height,
        archive_path=f"images/{capture_id}{suffix}",
    )
    return LoadedImage(asset=asset, pixels_bgr=pixels, original_bytes=raw)


def rotated_png_bytes(image: LoadedImage, quarter_turns: int) -> bytes:
    turns = quarter_turns % 4
    pixels = image.pixels_bgr
    if turns:
        pixels = np.rot90(pixels, k=-turns).copy()
    ok, encoded = cv2.imencode(".png", pixels)
    if not ok:
        raise ValueError("Could not encode rotated image")
    return encoded.tobytes()
```

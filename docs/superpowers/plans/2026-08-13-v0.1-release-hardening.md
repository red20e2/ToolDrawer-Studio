# V0.1 Release Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship ToolDrawer Studio 0.1.0 as a verified self-contained Windows x64 app with installer, portable bundle, diagnostics, unsaved-work protection, packaged-app tests, and a reproducible pre-release pipeline.

**Architecture:** Runtime hardening stays in focused Python modules; packaging stays under `packaging/`. One Python version source drives package/UI/installer/tag checks. Unsaved edits use a deterministic project fingerprint that excludes derived `generation_state`. PyInstaller builds a windowed one-directory app; Inno Setup wraps it; CI verifies source and frozen execution.

**Tech Stack:** Python 3.12, PySide6, CadQuery/OCP, NumPy, OpenCV, Shapely, pytest, PyInstaller, Inno Setup 6, PowerShell, GitHub Actions Windows.

## Global Constraints
- Version `0.1.0`, tag `v0.1.0`, Windows x64.
- Per-user installer, no admin or Python requirement.
- Keep 10 recent projects; persist project, export, and photo directories.
- Settings/logs: `%LOCALAPPDATA%\ToolDrawer Studio`.
- Artifacts: `ToolDrawer-Studio-0.1.0-Setup.exe`, `ToolDrawer-Studio-0.1.0-Portable.zip`, `SHA256SUMS.txt`.
- No updater, `.tds` association, MSIX, telemetry, cloud sync, mandatory signing, or V0.2 features.
- Frozen self-test + installer build are merge gates.
- Tag release is pre-release until physical validation passes.
- Merge/tag only with explicit user authorization.
